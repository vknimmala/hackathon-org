# AGENTS.md

## Project Overview

This repo contains the SurgeVector.ai Hackathon 2026 website generated from Lovable and adapted for local development/deployment.

The active app lives at the repository root:

- `src/` - TanStack Start React app source
- `supabase/` - Supabase config and migrations
- `public assets` are imported from `src/assets/`

There is also an untracked Lovable export folder (`surge-attendee-hub-main/`). Treat it as duplicate source material unless the user explicitly asks to compare or re-import from it. Make changes in the root app.

## Tech Stack

- React 19 with TypeScript
- TanStack Start, TanStack Router, and TanStack Query
- Vite with `@lovable.dev/vite-tanstack-config`
- Tailwind CSS v4
- Radix/shadcn-style UI components under `src/components/ui/`
- Supabase Auth and database via `@supabase/supabase-js`
- Sonner for toast notifications

## Commands

Use Node.js `>=22.12.0`. TanStack Start, Wrangler, and related packages warn or may fail on Node 20.

Prefer Bun because the repo includes `bun.lock`.

```bash
bun install
bun run dev
bun run build
bun run lint
bun run format
```

If Bun is unavailable, use the equivalent package-manager commands without adding a second lockfile unless the user approves.

## App Structure

- `src/routes/__root.tsx` defines global metadata, fonts, stylesheet links, the root shell, React Query provider, toaster, 404, and error UI.
- `src/routes/index.tsx` is the public landing page with the hero banner, journey timeline, FAQ, and registration CTA.
- `src/routes/register.tsx` contains participant registration form validation and writes to Supabase `registrations`.
- `src/routes/admin.tsx` contains Supabase Auth login/signup, admin role checks, registration review, status updates, search, and CSV export.
- `src/router.tsx` creates the TanStack Router and QueryClient.
- `src/routeTree.gen.ts` is generated by TanStack Router. Do not edit it manually.
- `src/components/site/` contains shared `Header` and `Footer`.
- `src/components/ui/` contains reusable UI primitives. Follow existing component patterns before adding new UI abstractions.
- `src/integrations/supabase/client.ts` creates the browser/SSR Supabase client.
- `src/integrations/supabase/types.ts` contains generated Supabase types. Regenerate/update from schema changes instead of hand-editing where possible.

## Supabase Model

Current migrations define:

- `public.app_role` enum: `admin`, `user`
- `public.user_roles`
  - Maps Supabase Auth users to roles.
  - Admin access is checked with `public.has_role(user_id, 'admin')`.
- `public.registration_type` enum: `Participant`, `Volunteer`
- `public.registration_status` enum: `pending`, `approved`, `rejected`
- `public.registrations`
  - Stores participant/volunteer submissions.
  - Includes participant fields like `team_name`, `team_members`, `idea_title`, `idea_description`, and `status`.

RLS intent:

- Anyone can insert a registration.
- Only authenticated admins can read/update/delete registrations.
- Users can read their own roles.
- Admins can read all roles.

When changing registration fields, update all of these together:

- Supabase migration
- Supabase generated types
- `src/routes/register.tsx`
- `src/routes/admin.tsx`
- CSV export headers in `src/routes/admin.tsx`

## Environment Variables

Do not commit real secret values. Never expose Supabase service-role keys in client code or `VITE_*` variables.

The current Supabase client expects:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_URL` for SSR fallback
- `SUPABASE_PUBLISHABLE_KEY` for SSR fallback

For Vercel, configure environment variables in the Vercel project settings for the relevant environments. Because browser code only receives `VITE_*` variables at build time, set the `VITE_` variables before building/deploying. Keep service-role keys out of Vercel unless a server-only function explicitly needs them.

## Deployment Notes

The repo currently has Cloudflare/Wrangler configuration (`wrangler.jsonc`) and Lovable's TanStack Vite config. The user also intends to deploy/configure Vercel env vars, so confirm the target platform before changing deployment config.

`vite.config.ts` intentionally uses `@lovable.dev/vite-tanstack-config`. That package already installs several plugins and aliases. Do not manually add duplicate plugins for React, Tailwind, TanStack Start, `tsconfig` paths, Cloudflare, or Lovable tagging unless the config package is removed.
